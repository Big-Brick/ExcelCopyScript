# ExcelCopyScript

Невелика настільна Python-програма для перенесення значень із кількох Excel-файлів у один підсумковий файл.

## Профілі та міграція

**Новий профіль** зберігає структуру вихідного та вхідного Excel, а також всі аліаси в **одному JSON-файлі**. Під час першого запуску нової версії створюється `~/.config/excel-copy-script/profiles/default.json`: дані переносяться з наявного `~/.config/excel-copy-script/aliases.json`, **не змінюючи і не видаляючи старий файл**. Програма читає останній обраний профіль із `~/.config/excel-copy-script/profile_state.json`. Якщо він відсутній або пошкоджений, користувач отримує повідомлення, а наявні профілі не перезаписуються.

Кнопка **«Відкрити профіль…»** дозволяє перейти на інший JSON після запуску, а **«Зберегти копію профілю…»** створює незалежну копію з поточними аліасами. Профіль можна відредагувати звичайним текстовим редактором і повторно відкрити, щоб застосувати параметри. У разі перемикання програма не змінює вже записані Excel-дані і не використовує попередній результат імпорту як результат нового профілю. Якщо підсумковий файл сумісний, він лишається відкритим; для повторного імпорту можна скористатися кнопкою «Повний перезапуск». Якщо новий профіль вимагає інший вихідний аркуш, необхідно вибрати відповідний підсумковий файл.

Основні поля `layout` нового профілю:

| Ключ | Початкове значення | Значення |
|---|---|---|
| `destination_sheet` | `Дані_підрозділів` | Назва вихідного аркуша |
| `header_row` | `3` | Рядок заголовків у підсумковій книзі |
| `first_data_row` | `4` | Перший рядок для результатів |
| `first_destination_column` | `2` | Перша дозволена для запису колонка (2 = B; усі колонки лівіше ігноруються) |
| `source_name_column` | `2` | Колонка назви в джерелі (2 = B) |
| `first_source_row` | `1` | З якого рядка починати читання джерела |
| `source_value_first_column` | `3` | Перша колонка кандидатів на значення (3 = C) |
| `source_value_last_column` | `7` | Остання колонка значень (7 = G) |
| `preferred_source_sheet` | `ВИСНОВКИ` | Який із присутніх вхідних аркушів вибирати в UI за замовчуванням |

Секція `aliases` містить усі шаблони, назви аркушів, колонки значень і специфічні рядкові прив’язки з формату v4. Під час роботи зміни аліасів зберігаються **в активному профілі**, а не в старому `aliases.json`.

**Що забекапити:** найважливіше — `~/.config/excel-copy-script/aliases.json`, а також старі `aliases.json.v*.bak` (за наявності). Найпростіше зберегти всю теку конфігурації:

~~~bash
cp -a ~/.config/excel-copy-script ~/excel-copy-script-backup
~~~

У цю копію також потраплять старі налаштування вікон `layout.json`, шляхи каталогів `recent_directories.json`, нові профілі та `profile_state.json`. **Профіль не є резервною копією вихідного Excel-файлу.**

## Як працює

- У підсумковому файлі .xlsx використовується аркуш **Дані_підрозділів**: назви параметрів розміщені в **рядку 3** (лише стовпчики **B** і далі), записи — починаючи з **рядка 4**. **Стовпчик A — порядковий номер**, його програма повністю ігнорує та не змінює.
- У кожному вхідному .xlsx читаються **всі аркуші**: назва параметра в **B**, а можливі значення у **C:G**. Аркуш **ВИСНОВКИ** не є обов'язковим. **Усі значення з будь-якого аркуша копіюються автоматично виключно за збереженими аліасами.** Навіть повний збіг назви параметра із заголовком підсумкового файлу не запускає копіювання без аліаса.
- Пошук **збережених аліасів** ігнорує регістр, додаткові пробіли та відмінності Unicode-представлення назв. Для ручного зіставлення на вкладці створення виберіть аркуш, вхідний рядок, **колонку значення C–G** (зі списку «Значення з:» або натисканням клітинки у правій частині таблиці) та вихідний стовпчик, після чого натисніть **«Копіювати вибрану пару + запам'ятати аліас»**.
- Головне вікно має **дві вкладки**: **«Аналіз і видалення аліасів»** (скопійовані значення + вхідні рядки) та **«Створення аліасів»** (усі вихідні стовпчики + вхідні рядки). На вкладці створення **всі вихідні стовпчики** відображаються незалежно від того, чи були вони вже заповнені в поточному імпорті. Заповнені позначені зеленим, а в колонці «Джерело значення» показані аркуш, комірка та назва вхідного параметра. **Жовтим позначаються вихідні стовпчики, для яких у поточному вхідному файлі знайшовся аліас, але копіювання за ним не спрацювало** (наприклад, через конфлікт або порожнє значення). У «Джерело значення» показано вхідний рядок та причину пропуску. Якщо хоча б одне значення у вихідний стовпчик успішно скопійовано, він залишається зеленим; без аліаса або без поточних проблем підсвічування немає. Повторно скопіювати дані в ці стовпчики не можна. На кожній вкладці є власний вибір аркуша. **Відображаються всі рядки** вибраного аркуша, навіть без текстової назви або значення. Сірі рядки не придатні для копіювання; **зелені справді скопійовані за чинним аліасом**, а **жовті мають аліас, але значення не перенесене** (наприклад, через конфлікт, порожню клітинку або повторювану назву). Оберіть жовтий рядок, щоб побачити причину пропуску під таблицею. Ліворуч завжди залишаються видимими **вихідний стовпчик аліаса, номер рядка та назва**; праворуч показані C:G із незалежною горизонтальною прокруткою. **Межу між цими двома областями можна перетягувати мишею**, змінюючи їхню ширину незалежно на кожній вкладці. На початку вибрано **ВИСНОВКИ**.
- Аліаси зберігаються **в активному файлі профілю** (для першого запуску — `~/.config/excel-copy-script/profiles/default.json`), окремо для кожного набору заголовків підсумкового файлу та **кожного аркуша джерела**. Старий `aliases.json` після міграції зберігається незмінним. Кожен аліас містить **номер вхідного стовпчика значення**, а також цільовий заголовок і стовпчик. Дві однакові назви з різних аркушів мають незалежні аліаси. Формат **v4** підтримує загальний аліас і додаткові аліаси, прив’язані до конкретного номера рядка. Загальний працює з усіма рядками з відповідною назвою; прив’язаний до рядка застосовується тільки до заданого аркуша, рядка **та** назви. У разі конкуренції аліасів однакової назви за одну вихідну колонку переважає єдиний аліас із прив’язаним рядком. На вкладці створення є прапорець **«Аліас лише для цього рядка»**. У вікні керування аліасами доступний стовпчик «Рядок» із позначенням «Усі» для загальних аліасів; кожний варіант можна видалити окремо. Старі формати v1/v2/v3 автоматично мігрують у v4 як загальні аліаси (для v1/v2 колонка значення — C). Перед міграцією створюється `aliases.json.v1.bak`, `aliases.json.v2.bak` або `aliases.json.v3.bak`.
- На вкладці **«Створення аліасів»** клацніть **правою кнопкою миші** по вхідному рядку або колонці значень C:G, щоб видалити його збережений аліас. Правий клік по вихідному стовпчику показує аліаси, які до нього ведуть, навіть якщо їх немає в поточному вхідному файлі. Якщо таких аліасів кілька, можна вибрати конкретний. Видалення потребує підтвердження, прибирає зелену позначку біля вхідного рядка, але **не видаляє вже записані значення Excel**.
- На вкладці **«Аналіз і видалення аліасів»** виберіть скопійований запис, пов'язаний зі збереженим аліасом, і натисніть **«Видалити аліас вибраного запису»**. Після видалення запис залишається в історії поточного імпорту з поміткою **«Аліас видалено»**, але аліас більше не застосовується до нових файлів. Кнопка **«Керувати всіма аліасами»** відкриває повний список збережених відповідностей для поточного шаблону, навіть якщо їх немає в поточному файлі. Видалення не змінює вже записані значення Excel.
- **Очищення підсумкової робочої області стало необов'язковим.** Прапорець **«Очищати робочу область»** у верхній панелі за замовчуванням **вимкнений**. За вимкненого прапорця відкриття підсумкової книги не змінює її даних. Під час імпорту програма порівнює лише значення, отримані через аліаси, з існуючими рядками: якщо **повний збіг рівно один**, значення перезаписуються в цей рядок; якщо **повних збігів кілька** або **повного немає, але є часткові**, відкривається діалог із варіантами вибрати існуючий рядок для перезапису, створити новий рядок або скасувати імпорт. Якщо збігів немає, створюється новий рядок. Під час перезапису інші колонки не змінюються; ручне копіювання може дозаповнити або перезаписати колонки обраного рядка. Скасування діалогу не змінює книгу. Якщо прапорець увімкнений, при відкритті підсумкового файлу робоча область очищується, а подальший імпорт послідовно додає нові рядки без пошуку збігів.
- Для наступного документа натисніть **«Відкрити вхідний / наступний файл»**. Підсумковий файл залишається відкритим у програмі. Кожен успішний запис відразу зберігається на диск.
- Кнопка **«↻ Повний перезапуск»** **за увімкненого прапорця очищає**, а **за вимкненого зберігає** підсумкову таблицю та **повторно імпортує всі успішно відкриті вхідні файли поточного сеансу в початковому порядку**, заново зчитуючи збережені аліаси й актуальний вміст файлів. Вибирати файли вдруге не потрібно. Ручні копіювання відтворюються лише через вже збережені аліаси. Якщо якийсь файл недоступний або імпорт завершується помилкою, попередній підсумковий Excel-файл не змінюється; список вибраних файлів зберігається для повторної спроби. Тимчасовий файл для атомарної заміни видаляється після завершення (резервної копії не створюється).
- **Таблиця вхідних рядків на вкладці створення використовує майже всю висоту сусідньої таблиці вихідних стовпчиків**: заголовок і вибір аркуша/колонки зібрані в один ряд, а порожній рядок з попередженням не займає місця. Якщо вибрати вхідний параметр із проблемним аліасом, пояснення тимчасово з’явиться під таблицею. Основне вікно відкривається висотою до 900 px (залежно від висоти екрана). Це дозволяє бачити більше рядків, не змінюючи масштаб тексту, ширини колонок або положення розділювачів.
- **Ширини колонок та положення розділювачів запам'ятовуються між запусками.** Зміни у всіх таблицях обох вкладок, а також у вікні керування аліасами зберігаються після перетягування мишею. Зовнішні розділювачі між таблицями й внутрішні розділювачі між назвами та C:G відновлюються окремо для кожної вкладки. Налаштування зберігаються в `~/.config/excel-copy-script/layout.json` (окремо від аліасів та Excel-файлів). Пошкоджений або відсутній файл налаштувань не заважає запуску програми.
- Програма **запам'ятовує останні теки** вибору підсумкових і вхідних файлів **окремо**. Наступного разу діалог відкриття файлу починається у відповідній теці, навіть після перезапуску. Дані зберігаються у `~/.config/excel-copy-script/recent_directories.json`. Якщо раніше вибрана тека недоступна, для вхідних файлів використовується тека поточної підсумкової книги, а інакше — домашня тека. Скасування діалогу чи невдалий імпорт не змінює збереженого шляху.

## Установлення (Ubuntu)

Потрібні Python 3.10+ і Tkinter. Якщо Tkinter відсутній:

~~~bash
sudo apt install python3-tk python3-venv
~~~

Із каталогу репозиторію:

~~~bash
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -m excel_copy_script
~~~

Альтернативно, після встановлення пакета:

~~~bash
.venv/bin/excel-copy-script
~~~

Старий спосіб запуску `.venv/bin/python excel_copy.py` теж працює.

## Структура проєкту

~~~text
excel_copy.py                     # Сумісна точка входу для старого запуску
pyproject.toml                    # Метадані пакета, залежності й GUI-команда
excel_copy_script/
  __init__.py                     # Публічні імпорти без ініціалізації GUI
  __main__.py                     # Запуск через python -m
  config.py                       # Значення за замовчуванням для сумісності
  workbook_layout.py              # Параметри координат і аркушів профілю
  profiles.py                     # Завантаження / перемикання / збереження профілів
  profile_migrations.py           # Неруйнівна міграція aliases.json у профіль
  models.py                       # Моделі параметрів та результату імпорту
  utils.py                        # Нормалізація назв і перевірка значень
  aliases.py                      # Персистентне збереження аліасів
  migrations.py                   # Міграції аліасів v1/v2/v3 -> v4 (прив'язка до рядка)
  recent_directories.py          # Персистентні теки для діалогів відкриття
  alias_dialog.py                 # Перегляд і видалення всіх збережених аліасів
  source_rows_panel.py           # Закріплені колонки та горизонтально прокручувані C:G
  workbook.py                     # Читання, зіставлення і запис Excel
  gui.py                          # Дві вкладки та обробники кнопок
tests/
  test_engine.py                  # Тести імпорту та аліасів
  test_package.py                 # Перевірка структури й точок входу
~~~

Бізнес-логіка у `workbook.py` не залежить від Tkinter; GUI лише викликає її методи.

## Важливі особливості

- Програма підтримує **.xlsx**, не старі .xls і не .xlsm. Перед імпортом **закрийте підсумкову книгу в Excel/LibreOffice**, щоб зовнішня програма не перезаписала зміни.
- **Тільки якщо прапорець «Очищати робочу область» увімкнено**, під час відкриття підсумкового файлу програма видаляє значення від **рядка 4 до кінця** на аркуші **Дані_підрозділів**, причому **лише в стовпчиках із заголовками, куди дозволений імпорт**. Очищення одразу зберігається на диск; заголовки, номери у A, інші стовпчики, інші аркуші та форматування залишаються без змін. За вимкненого прапорця початковий файл не очищується; порівняння аліасів допомагає обрати існуючий рядок або наступний порожній.
- За збереженими аліасами копіюються лише рядки, де B містить текст і обрана колонка значення непорожня. Для ручного вибору достатньо непорожнього значення в одному зі стовпчиків C:G. Усі інші рядки залишаються у сірому вигляді, щоб можна було зрозуміти структуру вхідного аркуша.
- Якщо назва параметра дублюється **на одному аркуші** або кілька аліасів із будь-яких аркушів претендують на один стовпчик, автоматичне копіювання конфліктних значень пропускається. Користувач вирішує такі випадки вручну.
- Формули у вхідних колонках C:G копіюються **як останні збережені результати**, не як формули. Якщо Excel-файл не містить кешованого результату, рядок пропускається з попередженням; спочатку відкрийте файл у Excel/LibreOffice, перераховуйте формули і збережіть.
- Вміст інших комірок і наявне форматування підсумкового файлу не змінюються навмисно, але openpyxl не гарантує повного збереження всіх складних можливостей Excel (особливо зовнішніх об'єктів). Для важливих оригіналів працюйте з копією.
- **Автоматичні резервні копії підсумкового .xlsx не створюються.** Очищення й подальший запис відразу зберігають обраний файл через тимчасовий файл і атомарне перейменування. Якщо попередні дані потрібні, збережіть копію самостійно.
- Аліас належить назві параметра, а не номеру рядка у вхідній таблиці. Для дубльованих заголовків підсумкової таблиці аліас запам'ятовує і номер стовпчика. Аліаси старих версій (які враховували заголовок A) автоматично переносяться на новий шаблон; відповідності, що вказували на A, не переносяться.
