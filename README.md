# ExcelCopyScript

Невелика настільна Python-програма для перенесення значень із кількох Excel-файлів у один підсумковий файл.

## Як працює

- У підсумковому файлі .xlsx використовується аркуш **Дані_підрозділів**: назви параметрів розміщені в **рядку 3** (лише стовпчики **B** і далі), записи — починаючи з **рядка 4**. **Стовпчик A — порядковий номер**, його програма повністю ігнорує та не змінює.
- У кожному вхідному .xlsx читаються **всі аркуші**: назва параметра в **B**, значення в **C**. Аркуш **ВИСНОВКИ** має бути присутнім, а **автоматичний збіг назв** дозволений **лише** на ньому. Дані з решти аркушів копіюються автоматично **виключно за раніше збереженими аліасами**; інакше доступні для ручного зіставлення.
- Автоматичне зіставлення ігнорує регістр, додаткові пробіли та відмінності Unicode-представлення. Якщо назви різні або параметр розміщено на іншому аркуші, користувач вручну вибирає вхідний рядок (із назвою аркуша) і вихідний стовпчик та натискає **«Копіювати вибрану пару + запам'ятати аліас»**.
- Виводяться три списки: скопійовані значення, невідповідні вихідні стовпчики та невідповідні вхідні рядки. Обидва останні списки оновлюються після ручного копіювання.
- Аліаси зберігаються в **~/.config/excel-copy-script/aliases.json**, окремо для кожного набору заголовків підсумкового файлу та **кожного аркуша джерела**. Дві однакові назви з різних аркушів мають незалежні аліаси. Порядок стовпчиків може змінюватися: для унікальних назв аліас і надалі працює. Міграція з версії 1 до версії 2 додає всім старим аліасам аркуш **ВИСНОВКИ** і створює одноразову копію `aliases.json.v1.bak`.
- Кнопка **«Керувати аліасами»** (після відкриття підсумкового файлу) показує всі збережені відповідності для поточного шаблону. Виберіть одну й натисніть **«Видалити вибраний аліас»**, підтвердивши дію. Видалення зберігається відразу; вже перенесені значення не змінюються, лише наступні імпорти перестануть використовувати цей аліас.
- Для наступного документа натисніть **«Відкрити вхідний / наступний файл»**. Підсумковий файл залишається відкритим у програмі. Кожен успішний запис відразу зберігається на диск.
- Програма **запам'ятовує останні теки** вибору підсумкових і вхідних файлів **окремо**. Наступного разу діалог відкриття файлу починається у відповідній теці, навіть після перезапуску. Дані зберігаються у `~/.config/excel-copy-script/recent_directories.json`. Якщо раніше вибрана тека недоступна, для вхідних файлів використовується тека поточної підсумкової книги, а інакше — домашня тека. Скасування діалогу чи невдалий імпорт не змінює збереженого шляху.

## Установлення (Ubuntu)

Потрібні Python 3.10+ і Tkinter. Якщо Tkinter відсутній:

~~~bash
sudo apt install python3-tk python3-venv
~~~

Із каталогу репозиторію:

~~~bash
python3 -m venv .venv
.venv/bin/pip install -e .
.venv/bin/python -m excel_copy_script
~~~

Альтернативно, після встановлення пакета:

~~~bash
.venv/bin/excel-copy-script
~~~

Старий спосіб запуску `.venv/bin/python excel_copy.py` теж працює.

## Структура проєкту

~~~text
excel_copy.py                     # Сумісна точка входу для старого запуску
pyproject.toml                    # Метадані пакета, залежності й GUI-команда
excel_copy_script/
  __init__.py                     # Публічні імпорти без ініціалізації GUI
  __main__.py                     # Запуск через python -m
  config.py                       # Назви аркушів і координати
  models.py                       # Моделі параметрів та результату імпорту
  utils.py                        # Нормалізація назв і перевірка значень
  aliases.py                      # Персистентне збереження аліасів
  migrations.py                   # Перехід зі старого формату аліасів на sheet-aware v2
  recent_directories.py          # Персистентні теки для діалогів відкриття
  alias_dialog.py                 # Перегляд і видалення аліасів
  workbook.py                     # Читання, зіставлення і запис Excel
  gui.py                          # Tkinter-інтерфейс і обробники кнопок
tests/
  test_engine.py                  # Тести імпорту та аліасів
  test_package.py                 # Перевірка структури й точок входу
~~~

Бізнес-логіка у `workbook.py` не залежить від Tkinter; GUI лише викликає її методи.

## Важливі особливості

- Програма підтримує **.xlsx**, не старі .xls і не .xlsm. Перед імпортом **закрийте підсумкову книгу в Excel/LibreOffice**, щоб зовнішня програма не перезаписала зміни.
- За вільний береться **перший рядок починаючи з четвертого, у якому всі стовпчики B і далі порожні**. Наявність порядкового номера в A не заважає використанню рядка; заповнені дані в інших стовпчиках не перезаписуються.
- Автоматично обробляються лише рядки, де B містить текст, а C — непорожнє значення. Примітки, що також мають B/C, можуть з'явитися у списку невідповідних — їх можна просто ігнорувати.
- Якщо назва параметра дублюється **на одному аркуші** або кілька параметрів із будь-яких аркушів претендують на один стовпчик, автоматичне копіювання конфліктних значень пропускається. Користувач вирішує такі випадки вручну.
- Формули у вхідній колонці C копіюються **як останні збережені результати**, не як формули. Якщо Excel-файл не містить кешованого результату, рядок пропускається з попередженням; спочатку відкрийте файл у Excel/LibreOffice, перераховуйте формули і збережіть.
- Вміст інших комірок і наявне форматування підсумкового файлу не змінюються навмисно, але openpyxl не гарантує повного збереження всіх складних можливостей Excel (особливо зовнішніх об'єктів). Для важливих оригіналів працюйте з копією.
- Перед **першим записом за запуск** створюється резервна копія у каталозі підсумкового файлу: ім'я.backup-ДАТА.xlsx. Сам файл зберігається через тимчасовий файл і атомарне перейменування.
- Аліас належить назві параметра, а не номеру рядка у вхідній таблиці. Для дубльованих заголовків підсумкової таблиці аліас запам'ятовує і номер стовпчика. Аліаси старих версій (які враховували заголовок A) автоматично переносяться на новий шаблон; відповідності, що вказували на A, не переносяться.
